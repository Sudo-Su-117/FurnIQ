



FurnIQ Application Page Flow Implementation Guide

Admin loop, purchase and sales branches, required fields, features, and system effects
This document converts the Urban Furniture Accounting System PDF and the workflow image into a practical build guide for the hackathon team. It explains what each page should show, which fields are required, which actions must exist, and what effect each action should create in inventory, payments, accounting entries, reports, and dashboard data.


Scope Rule
This is an internal accounting and inventory record system. It is not an ecommerce marketplace. Admin and accountant users create digital records that mirror offline customers, vendors, products, purchases, sales, bills, invoices, payments, and reports.

Branching After Journals
After Contacts, Products, Accounts, and Journals are ready, the system can branch into Purchase or Sales. For the demo, run Purchase first so stock exists before the Sales flow.

Branch

Flow

Main result

Purchase branch

Purchase Order -&gt; Vendor Bill -&gt; Vendor Payment

Stock increases, payable is created, payment clears payable.

Sales branch

Sales Order -&gt; Customer Invoice -&gt; Customer Payment

Stock decreases, receivable is created, payment clears receivable.

Reporting close

Reports -&gt; Dashboard

Financial, stock, and dashboard numbers prove the loop worked.

Definition Of Done


Admin can create contacts, products, accounts, journals, and budgets.


Purchase order can become vendor bill.


Vendor bill posting increases stock and creates accounting entry.


Vendor payment reduces payable and creates accounting entry.


Sales order can become customer invoice.


Customer invoice posting decreases stock and creates accounting entry.


Customer payment reduces receivable and creates accounting entry.


Reports show Balance Sheet, Profit and Loss, Budget Report, and Stock Report from real data.


Dashboard reflects the completed transaction loop.


Contact user sees only their own invoices or bills.
